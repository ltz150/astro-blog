## Web Analytics

在 Cloudflare 的 **Workers & Pages → astro-blog（Pages）→ 指标 → Web Analytics** 中启用。控制台已确认启用，下一次部署才开始向页面插入脚本。

Cloudflare Web Analytics 脚本只由 Pages 自动注入，避免重复安装 Cloudflare beacon。2026-10-02 按用户确认的方案另接入自建 HanAnalytics：`src/config.ts` 中的 `HanAnalytics` 配置自己的统计域名，页脚加载其轻量 tracker。两个统计服务分别记录数据，统计口径可能不同。

查看数据：进入同一页面，点击 **查看 Web Analytics**。上线后需要真实浏览器访问并等待数据汇总；启用不会补录此前的历史访问。

## 本次改动

1. **首屏背景图**：保留原始 `home-banner.webp`，另外生成带内容哈希的两个 WebP。
   - 桌面：1920 × 1080，597,728 字节。
   - 移动：800 × 850，168,792 字节，约 165 KiB。
   - 原图：3840 × 2160，约 2.8 MiB。移动版本减小约 94%。
   - 背景路径统一保存在 `src/config.ts` 的 `bannerImages` 中。CSS 和带媒体条件的高优先级预加载使用同一份配置，避免手机下载桌面大图。
2. **字体**：移除全站中文字体分包 CSS 请求，使用本机中文无衬线字体；代码块使用本机等宽字体。不同操作系统的字形会有少量差异。
3. **组件按需加载**：首页不下载 APlayer 或 Waline 样式；含音乐的文章才加载 APlayer。样式通过 Vite `?url` 和现有 `LoadStyle` 加载，避免 Astro 把动态 CSS 导入也提升为全站样式。
4. **搜索**：不在首次打开网页时下载整份搜索索引；输入关键词时再加载。
5. **图片**：卡片、侧边栏图片使用原生懒加载及尺寸属性；首屏头像直接使用真实地址。旧的图片懒加载脚本跳过已有原生加载属性的图片，避免替换真实图片后重复下载。
6. **远程缩略图**：已有 WordPress 图片代理封面增加宽度 800 和质量 75 参数，减少卡片请求的大图尺寸。
7. **可访问性**：允许手机缩放；列表标题使用一级标题和二级文章标题，摘要及标签不再伪装为标题；增强灰色文字和页脚徽章的对比度。
8. **缓存**：在 `public/_headers` 为带哈希的 `vh_static` 产物和两张新背景图设置一年缓存。HTML 不设永久缓存，保证文章更新及时生效。
9. **手机首屏稳定显示**：座右铭在 HTML 中直接提供，手机或减少动态效果模式下不逐字播放，也不运行背景气泡动画；桌面普通模式保留动态效果。
10. **响应式与尺寸补全**：WordPress 代理卡片提供 400w / 800w 的 `srcset`，浏览器根据显示宽度和像素密度选择；七张页脚徽章按 SVG 原始尺寸声明宽高并懒加载。

随后针对这份复测报告继续稳定手机座右铭和背景动画，并补齐卡片响应式尺寸及页脚图片宽高。

## 继续维护

替换背景图时，先压缩并生成新的文件名，再更新 `bannerImages` 和 `_headers`；不要直接覆盖已设置长期缓存的旧文件。

未来测速应在正式部署后重新生成。先确认新 HTML、背景文件和 Cloudflare beacon 已上线，再运行移动端 PageSpeed；将新的分数、FCP、LCP 与上表比较，保留结果链接。实际用户数据需要访问积累，不能把一次实验室高分等同于所有地区的实际速度。
