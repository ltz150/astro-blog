对象存储迁移不仅要证明文件上传成功，还要确认对象范围、失败重试、元数据和删除行为符合业务要求。

## 技术在哪些项目用到

| 项目 | 使用方式 | 资料证据 |
| --- | --- | --- |
| 项目 D | 本地／NAS 文件到 OSS 的演示 | ossimport 配置、工具包说明及演示计划 |
| 项目 H | 多个 OSS 实例全量与增量迁移 | 问题记录，包含源端删除不能同步到目标端的限制 |
| 项目 K | OSS 方案、部署和小范围迁移测试 | 进度笔记记录测试成功；没有最终对象校验报告 |

## 项目背景

项目 D 的历史 `local_job` 配置选择本地源，并关闭了增量模式。这说明它对应全量配置，不能写成已运行增量同步。项目 H 的问题记录则描述了另一种状态：全量已经完成，增量任务继续运行，但删除行为不符合镜像一致性的要求。

## 实施步骤

1. **确认工具版本与源类型。** 项目 D 归档的是 ossimport 2.3.5。旧版配置与其他迁移产品的能力不能混用。
2. **明确对象范围。** 核对目录／bucket、前缀、对象数量、大小和是否保留原目录结构。
3. **准备迁移节点。** 验证源端读取、目标端写入权限和网络带宽；凭据不进入命令示例或博客附件。
4. **配置任务。** 根据实际源类型填写路径及 endpoint。资料中的全量配置不能通过修改文章文字变成增量配置。
5. **选择一种启动流程。** 原工具提供一键导入和分步执行。应根据同版本 README 操作，保留工作目录与检查点。
6. **处理失败任务。** 读取 `audit.log` 并分类；源文件改变、源文件删除、命名不合法和下载失败应分别处理。
7. **执行一致性验证。** 建议检查对象数量、大小、抽样内容及业务元数据。ETag 的含义取决于上传方式，不能无条件视为文件 MD5。
8. **处理增量与割接。** 明确扫描间隔和变更范围，安排停写窗口并完成最后一轮验证。

## 问题与解决方法

### 源文件迁移过程中发生改变

工具 README 说明，这可能出现 `SIZE_NOT_MATCH`。应先确认源对象是否还在写入，再决定重试；不停变化的对象可能需要业务冻结或版本化快照。资料未给出此类问题在项目 D 的实际发生记录。

### 失败任务需要重试

旧工具支持仅重试失败 Task。先保留日志和检查点，再重试；不应为了重试盲目清除任务，否则可能破坏已有进度。具体命令依赖归档版本。

### 源端删除没有传播到目标端

项目 H 明确记录了这一限制，但“解决方案”部分没有填写内容，因此没有证据证明已解决。

可补充设计一个独立的删除一致性流程：在业务认可的快照边界生成源目标清单，过滤迁移范围，产生“疑似多余对象”报告，人工核对后再按批准的策略处理。不能直接按一次列表差集删除目标对象，因为目标端可能有独立数据或列表期间源端仍在变化。

## 已记录的测试结果

项目 K 的进度笔记记录了工具部署验证通过，并记录测试 bucket 到目标平台的迁移成功。这支持“小范围迁移测试成功”的表述，不能替代正式业务 bucket 的全量验收。

## 经验与结果边界

“增量同步”并不天然等于“完全镜像”。历史 README 中的规模选型和成本建议也不宜作为当前费用承诺；复用时需按实际版本和服务计费核查。
